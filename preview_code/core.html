What lives in core.pylines 1–19

All the numerical work that more than one stage needs, so that training and evaluation use exactly the same maths. The file has six parts, shown in its docstring: devices and repeat seeds; the Gaussian mixture; the network; the training recipe; the exact sampler; the anchors.

make_schedule(): how much noise at each steplines 42–49

Diffusion adds noise gradually. At step i a clean point x₀ has become

x_i = √ᾱ_i · x₀ + √(1 − ᾱ_i) · noise

where ᾱ ("alpha-bar") falls from almost 1 (clean) to near 0 (all noise). The betas βi are small per-step noise amounts, spaced evenly from beta_min = 10⁻⁴ to beta_max = 0.02, and ᾱi = (1−β₀)(1−β₁)…(1−βi).

Worth knowing: the total amount of noise depends on T. The betas are spread between the same two end values whatever T is, so fewer steps means less noise in total. At the seed end:

Tᾱ at the seed enddata signal left in a "seed"
1000.3660%
2000.1336%
5000.0068%
10000.000040.6%

The learned sampler uses T_train = 500; the exact sampler that builds the atlas uses T_true (200 by default). For DDIM, when the two differ, the exact backtrack and the learned sampler take the seed to be noise at different noise levels. The atlas then describes a slightly different seed space from the one it is scored on. Flow matching is not affected: its time grid always runs from 0 to 1. (This is an observation from reading the code, not something the code states.)

42# --------------------------------------------------------------------------------------
43# the Gaussian mixture: K isotropic modes N(mu_k, sigma^2 I) on a sphere of radius R
44# --------------------------------------------------------------------------------------
45def make_schedule(T: int = 1000, beta_min: float = 0.001, beta_max: float = 0.02,
46                  device=None) -> torch.Tensor:
47    """abar[i] = prod_{j<=i} (1 - beta_j) for linear betas: x_i = sqrt(abar) x0 + sqrt(1-abar) eps."""
48    abar = np.cumprod(1.0 - np.linspace(beta_min, beta_max, T))
49    return torch.tensor(abar, dtype=torch.float32, device=device)

r99(): the radius that holds 99% of a modelines 52–54

For a d-dimensional Gaussian with spread σ, the squared distance from the centre divided by σ² follows a chi-square distribution with d degrees of freedom. Its 99th percentile gives the radius:

R99 = σ · √(chi2.ppf(0.99, d))

With σ = 0.1: R99 = 0.30 at d = 2, 0.97 at d = 64, 2.43 at d = 512. In high d almost all the mass sits in a thin shell just inside R99, which is why small errors in high d push samples out of the ball.

52def r99(d: int, sigma: float, q: float = 0.99) -> float:
53    """Radius of the ball holding mass q of N(0, sigma^2 I_d) (chi-square): the mode boundary."""
54    return float(np.sqrt(chi2.ppf(q, d)) * sigma)

sample_modes(): where the K blobs golines 57–75

Draws K random directions, scales each to length R (the sphere radius) and accepts a new centre only if it is at least m_mult × 2 × R99 away from every centre already placed. With m_mult = 1.5 the 99% balls never touch and have a gap between them. If it cannot fit K centres after 10 000·K tries it gives up with a clear error; train.py then skips that cell.

Uses NumPy's old RandomState so that the placement is identical on every machine and device.

57def sample_modes(K, d, R, sigma, m_mult=1.5, seed=0, device=None):
58    """K means on the sphere of radius R, rejection-sampled so every pair is >= m_mult * 2 R99
59    apart (the 99% balls never overlap). Returns (means (K, d), min_sep)."""
60    min_sep = m_mult * 2 * r99(d, sigma)
61    rng = np.random.RandomState(seed)
62    modes = np.empty((K, d), dtype=np.float64)
63    n, tries = 0, 0
64    while n < K and tries < 10_000 * K:
65        tries += 1
66        v = rng.randn(d)
67        v *= R / np.linalg.norm(v)
68        if n and np.linalg.norm(modes[:n] - v, axis=1).min() < min_sep:
69            continue
70        modes[n] = v
71        n += 1
72    if n < K:
73        raise RuntimeError(f"placed only {n}/{K} modes for d={d}, K={K} (R={R}, sigma={sigma}, "
74                           f"min_sep={min_sep:.3f}); increase R or lower sigma/K")
75    return torch.tensor(modes.astype(np.float32), device=device), float(min_sep)

mode_weights(): equal or unequal blobslines 78–92

Unweighted (the default): every mode has probability 1/K.

Weighted (data.weighted=true): draw K numbers between 0.3 and 0.8 and normalise them, once per K. Each repeat seed then hands these same weights to the modes in its own shuffled order. So the spread across repeats comes from which mode gets which weight, not from new weights. Always drawn on the CPU so that GPU and CPU runs agree.

78WEIGHT_LO, WEIGHT_HI = 0.3, 0.8   # raw mixing weights are drawn from U[WEIGHT_LO, WEIGHT_HI]
79
80
81def mode_weights(K, seed, weighted, device=None, base_seed=0):
82    """Mixing weights (K,), uniform unless `weighted`. Weighted runs draw a single weight
83    profile per (K, base_seed) and let each repeat `seed` hand it out to the modes in its own
84    random order, so the spread over seeds comes from where the weights land, not from new
85    weights. Drawn on the CPU so the device does not matter."""
86    if not weighted:
87        return torch.full((K,), 1.0 / K, device=device)
88    g = torch.Generator().manual_seed(int(base_seed) + 13)
89    w = WEIGHT_LO + (WEIGHT_HI - WEIGHT_LO) * torch.rand(K, generator=g)
90    w = w / w.sum()
91    g = torch.Generator().manual_seed(int(seed) + 17)
92    return w[torch.randperm(K, generator=g)].to(device)

Training data: _draw_modes, gmm_train_set, _minibatchlines 95–128

  • _draw_modes: pick a mode for each sample (uniformly, or by the weights).
  • gmm_train_set: a fixed training set of n_train = 100 000 points, μk + σ·noise, reproducible from the seed.
  • _minibatch: returns a function draw() that gives one batch per call, either resampled from that fixed set or, if n_train is null, fresh from the mixture every time. All randomness comes from the generator g passed in (see step_generator).
 95def _draw_modes(K, n, weights, g, device):
 96    """n mode indices, uniform (weights None) or multinomial under `weights`."""
 97    if weights is None:
 98        return torch.randint(0, K, (n,), generator=g, device=device)
 99    return torch.multinomial(weights.to(device), n, replacement=True, generator=g)

102def gmm_train_set(means_t, n, variance, seed, device=None, weights=None):
103    """A fixed training set of n GMM draws, reproducible per seed. Returns (X, mode index)."""
104    K, d = means_t.shape
105    g = torch.Generator(device=device).manual_seed(int(seed) + 11)
106    k = _draw_modes(K, n, weights, g, device)
107    X = means_t[k] + math.sqrt(variance) * torch.randn(n, d, generator=g, device=device)
108    return X, k
109

111def _minibatch(means_t, variance, batch, n_train, seed, device, weights=None, g=None):
112    """Returns draw(), which gives one clean minibatch (batch, d): resampled from a fixed
113    training set of n_train points, or fresh mixture samples every step if n_train is None.
114    All randomness comes from the generator `g`."""
115    K, d = means_t.shape
116    if n_train:
117        X, _ = gmm_train_set(means_t, int(n_train), variance, seed, device, weights)
118
119        def draw():
120            return X.index_select(0, torch.randint(0, X.shape[0], (batch,), generator=g, device=device))
121    else:
122        sigma = math.sqrt(variance)
123        w = None if weights is None else weights.to(device)
124
125        def draw():
126            k = _draw_modes(K, batch, w, g, device)
127            return means_t[k] + sigma * torch.randn(batch, d, generator=g, device=device)
128    return draw

label_fate(): the rule that defines a hallucinationlines 131–138

The most important function in the repository. For each endpoint:

  1. measure the distance to every mode centre (torch.cdist);
  2. take the nearest;
  3. if it is within R99 the fate is that mode's index, otherwise −1.

It works in chunks of 50 000 points so that the distance matrix never gets too big for memory. Everything in the project (the ground truth, the anchor labels, the probe during training) is labelled by this one function.

131@torch.no_grad()
132def label_fate(Xf, means_t, R99, chunk=50000):
133    """Fate of each endpoint: its nearest mode if within R99 of it, else -1."""
134    lab = torch.empty(Xf.shape[0], dtype=torch.long, device=Xf.device)
135    for s in range(0, Xf.shape[0], chunk):
136        dmin, arg = torch.cdist(Xf[s:s + chunk], means_t).min(1)
137        lab[s:s + chunk] = torch.where(dmin <= R99, arg, torch.full_like(arg, -1))
138    return lab

SinusoidalPosEmb: telling the network the timelines 141–154

The network needs to know how noisy its input is. The step number t is turned into a vector of sines and cosines at many frequencies (the same trick transformers use for word positions), so that nearby steps get similar vectors and the network can tell steps apart easily.

141# --------------------------------------------------------------------------------------
142# the learned model: a residual MLP on (x, t) that predicts the noise (DDIM) or velocity (flow)
143# (submodule names are the checkpoint state_dict keys: keep them)
144# --------------------------------------------------------------------------------------
145class SinusoidalPosEmb(nn.Module):
146    def __init__(self, dim: int):
147        super().__init__()
148        self.dim = dim
149
150    def forward(self, t):
151        half = self.dim // 2
152        f = torch.exp(torch.arange(half, device=t.device) * -(math.log(10000) / (half - 1)))
153        a = t[:, None].float() * f[None, :]
154        return torch.cat([torch.sin(a), torch.cos(a)], 1)

MLPBlock and ScoreNet: the networklines 157–185

A plain residual MLP. Given a point x (d numbers) and a step t:

z = Linear(x) + Linear(time embedding of t) z = z + block(z) × 4 blocks, block = LayerNorm → act → Linear → act → Linear output = Linear(act(LayerNorm(z))) (d numbers)

For DDIM the output is the predicted noise; for flow matching it is a velocity. Same network either way. The activation is LeakyReLU(0.2). Hidden width h is 256 or 1024 (next piece).

The comment on line 143 matters: the attribute names (inp, te, tm, bl, out) are the keys saved in checkpoint files, so renaming them would make old checkpoints unloadable.

157class MLPBlock(nn.Module):
158    """x + Linear(act(Linear(act(LayerNorm(x)))))."""
159
160    def __init__(self, h, act):
161        super().__init__()
162        self.n, self.a = nn.LayerNorm(h), act
163        self.f1, self.f2 = nn.Linear(h, h), nn.Linear(h, h)
164
165    def forward(self, x):
166        return x + self.f2(self.a(self.f1(self.a(self.n(x)))))
167
168
169class ScoreNet(nn.Module):
170    H, NB, TD = 256, 4, 128          # defaults: hidden width, residual blocks, time-embedding dim
171
172    def __init__(self, d, h=H, nb=NB, td=TD):
173        super().__init__()
174        act = nn.LeakyReLU(0.2)
175        self.inp = nn.Linear(d, h)
176        self.te = SinusoidalPosEmb(td)
177        self.tm = nn.Sequential(nn.Linear(td, h), act)
178        self.bl = nn.ModuleList([MLPBlock(h, act) for _ in range(nb)])
179        self.out = nn.Sequential(nn.LayerNorm(h), act, nn.Linear(h, d))
180
181    def forward(self, x, t):
182        z = self.inp(x) + self.tm(self.te(t))
183        for b in self.bl:
184            z = b(z)
185        return self.out(z)

learned_closure(): one DDIM training steplines 206–224

Returns a fresh network and a function step() that computes one training loss. A function that remembers its surroundings like this is called a closure; it lets the optimiser code (next section) train any process without knowing its details.

One step, in words:

  1. take a batch of clean points x₀;
  2. pick a random step i for each;
  3. add the right amount of noise: x_i = √ᾱ_i·x₀ + √(1−ᾱ_i)·noise;
  4. ask the network to predict that noise; the loss is the mean squared error.

That is the standard "ε-prediction" diffusion loss.

206def learned_closure(means_t, d, K, abar, T, variance, batch=512, seed=0, device=None,
207                    n_train=None, weights=None, arch=None):
208    """A fresh ScoreNet (init seeded by `seed`) and its DDIM loss closure: MSE between the
209    network's noise prediction and the noise added to a minibatch at uniform random steps."""
210    torch.manual_seed(seed)
211    sa, soma = torch.sqrt(abar), torch.sqrt(1 - abar)
212    m = ScoreNet(d, **(arch or {})).to(device)
213    g = step_generator(seed, device)
214    draw = _minibatch(means_t, variance, batch, n_train, seed, device, weights, g)
215
216    def step():
217        x0 = draw()
218        ti = torch.randint(0, T, (batch,), generator=g, device=device)
219        noise = torch.randn(x0.shape, generator=g, device=device)
220        xt = sa[ti][:, None] * x0 + soma[ti][:, None] * noise
221        return ((m(xt, ti) - noise) ** 2).mean()
222
223    step.generator = g
224    return m, step

The training recipe: EMA warm-up and cosine learning ratelines 227–242

Two small helpers that give a number per step:

  • _ema_decay: how strongly the EMA (a running average of the weights) holds on to its past. It ramps up from about 0 over the first 1000 steps to 0.999.
  • _cosine_lr: the learning rate, falling from lr = 10⁻³ to lr_min = 10⁻⁵ along half a cosine. It reproduces PyTorch's CosineAnnealingLR exactly, because the CUDA-graph path below has to compute the whole table in advance.
227# --------------------------------------------------------------------------------------
228# the training recipe: Adam + cosine lr decay (lr -> lr_min) + grad-norm clip + an EMA of the
229# weights that replaces them at the end. Any piece is off when its setting is None / 0.
230# --------------------------------------------------------------------------------------
231def _ema_decay(step: int, decay: float, warmup: int) -> float:
232    """EMA decay, ramped up from ~0 over the first `warmup` steps."""
233    if warmup and step < warmup:
234        return min(decay, (1.0 + step) / (1.0 + warmup))
235    return decay
236
237
238def _cosine_lr(step: int, n_steps: int, lr: float, lr_min) -> float:
239    """The lr at `step` of torch's CosineAnnealingLR(T_max=n_steps, eta_min=lr_min)."""
240    if lr_min is None or n_steps <= 1:
241        return lr
242    return lr_min + (lr - lr_min) * 0.5 * (1.0 + math.cos(math.pi * step / n_steps))

run_optimizers(): train several models at oncelines 245–261

The recipe: Adam, cosine learning-rate decay, gradient clipping at norm 1, and an EMA of the weights that replaces the weights at the end (averaged weights usually sample better). Each piece is switched off by setting it to null.

Two implementations of the same maths:

  • eager: an ordinary Python loop. The reference, used on CPU.
  • CUDA graph: on a GPU. These networks are so small that a Python loop spends most of its time just launching GPU work. Recording one training step of all models once and replaying the recording is about 15× faster.

branch_streams=False exists because several multi-stream graphs from different processes on one GPU crashed with the driver in use ("illegal memory access").

245def run_optimizers(models, loss_closures, n_steps, lr=1e-3, lr_min=None, grad_clip=None,
246                   ema_decay=None, ema_warmup=0, cuda_graph=True, branch_streams=True):
247    """Train several independent models for `n_steps` steps each, model i on loss_closures[i]().
248    Returns the models (with their EMA weights when ema_decay is set).
249
250    On a GPU, one training step of all the models is recorded once as a CUDA graph (each model
251    on its own stream) and then replayed. The networks are small, so a plain Python loop spends
252    most of its time launching kernels; the graph does the same maths about 15x faster. The CPU / cuda_graph=False path is the
253    plain eager loop, the reference. branch_streams=False runs the branches one after another:
254    required when several such processes share a GPU (multi-stream graphs from concurrent
255    processes crash with 'illegal memory access' on driver 565 / torch 2.5)."""
256    assert len(models) == len(loss_closures) and models
257    if cuda_graph and next(models[0].parameters()).device.type == "cuda":

260    return [_run_optimizer_eager(m, c, n_steps, lr, lr_min, grad_clip, ema_decay, ema_warmup)
261            for m, c in zip(models, loss_closures)]

_run_optimizer_eager(): the plain looplines 264–289

Read this one to understand the recipe; the graph version does the same thing. Per step: compute the loss, back-propagate, clip the gradient, take an Adam step, advance the learning-rate schedule, update the EMA copy (ema = decay·ema + (1−decay)·weights). At the end, load the EMA weights into the model.

264def _run_optimizer_eager(model, loss_closure, n_steps, lr, lr_min, grad_clip, ema_decay, ema_warmup):
265    opt = torch.optim.Adam(model.parameters(), lr=lr)
266    sched = None
267    if lr_min is not None and n_steps > 1:
268        sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=n_steps, eta_min=lr_min)
269    ema = {k: v.detach().clone() for k, v in model.state_dict().items()} if ema_decay else None
270    for step in range(n_steps):
271        loss = loss_closure()
272        opt.zero_grad(); loss.backward()
273        if grad_clip is not None:
274            torch.nn.utils.clip_grad_norm_(model.parameters(), grad_clip)
275        opt.step()
276        if sched is not None:
277            sched.step()
278        if ema is not None:
279            dcy = _ema_decay(step, ema_decay, ema_warmup)
280            live = model.state_dict()
281            with torch.no_grad():
282                for k, v in ema.items():
283                    if v.dtype.is_floating_point:
284                        v.mul_(dcy).add_(live[k].detach(), alpha=1 - dcy)
285                    else:
286                        v.copy_(live[k])
287    if ema is not None:
288        model.load_state_dict(ema)
289    return model

_GraphBranch: one model inside the recordinglines 292–335

A CUDA graph replays the same GPU operations every time, so nothing may change on the Python side between replays. The tricks used:

  • The learning rate and EMA decay of every step are precomputed into tables on the GPU, and a step counter that lives on the GPU picks the current entry.
  • Adam is created with capturable=True (its internal step count also stays on the GPU).
  • Gradients are zeroed, not freed, because the recording owns those buffers.
  • The EMA update uses the fast _foreach operations on all weights at once.
292class _GraphBranch:
293    """One model's step inside the graph: capturable Adam, clip, foreach EMA. The lr / EMA decay

313    def step(self, step_t):
314        self.lr_t.copy_(self.lr_tab.index_select(0, step_t).squeeze(0))
315        self.closure().backward()
316        if self.grad_clip is not None:
317            torch.nn.utils.clip_grad_norm_(self.params, self.grad_clip, foreach=True)
318        self.opt.step()
319        self.opt.zero_grad(set_to_none=False)                    # the graph owns the grad buffers
320        if self.ema_f is not None:
321            self.dcy_t.copy_(self.dcy_tab.index_select(0, step_t).squeeze(0))
322            self.omd_t.copy_(1.0 - self.dcy_t)
323            with torch.no_grad():
324                torch._foreach_mul_(self.ema_f, self.dcy_t)
325                torch._foreach_add_(self.ema_f, torch._foreach_mul(self.live_f, self.omd_t))
326                for v, e in self.ema_o.values():
327                    e.copy_(v)
328
329    def finish(self):
330        if self.ema_f is not None:
331            float_w = iter(self.ema_f)
332            sd = self.model.state_dict()
333            self.model.load_state_dict({k: next(float_w) if sd[k].dtype.is_floating_point
334                                        else self.ema_o[k][1] for k in self.ema_keys})
335        return self.model

_run_optimizers_graph(): record once, replay many timeslines 338–379

  1. Build the learning-rate and EMA tables and a GPU step counter.
  2. Give each model its own CUDA stream so their steps run side by side.
  3. Run 3 real steps first (they create the optimiser's memory).
  4. Register each model's private random generator with the graph, so that every replay draws new random numbers, then record one round.
  5. Replay it for the remaining steps and hand back the models with EMA weights.
338def _run_optimizers_graph(models, loss_closures, n_steps, lr, lr_min, grad_clip,
339                          ema_decay, ema_warmup, branch_streams=True, n_warmup=3):
340    """CUDA-graph form of the eager loop (same per-step maths)."""
341    device = next(models[0].parameters()).device
342    n_warmup = min(n_warmup, n_steps)
343    lr_tab = torch.tensor([_cosine_lr(s, n_steps, lr, lr_min) for s in range(n_steps)],
344                          dtype=torch.float32, device=device)
345    dcy_tab = None
346    if ema_decay:
347        dcy_tab = torch.tensor([_ema_decay(s, ema_decay, ema_warmup) for s in range(n_steps)],
348                               dtype=torch.float32, device=device)
349    step_t = torch.zeros((1,), dtype=torch.long, device=device)   # on-device step counter
350    branches = [_GraphBranch(m, c, lr_tab, dcy_tab, grad_clip) for m, c in zip(models, loss_closures)]
351    streams = [torch.cuda.Stream() if branch_streams else None for _ in branches]
352
353    def one_round(parent):
354        # fork every branch off the parent stream, join them back, advance the counter
355        for b, s in zip(branches, streams):
356            if s is None:
357                b.step(step_t)
358                continue
359            s.wait_stream(parent)
360            with torch.cuda.stream(s):
361                b.step(step_t)
362        for s in streams:
363            if s is not None:
364                parent.wait_stream(s)
365        step_t.add_(1)
366
367    for _ in range(n_warmup):                  # real steps that allocate grads / Adam state
368        one_round(torch.cuda.current_stream())
369    if n_steps > n_warmup:
370        g = torch.cuda.CUDAGraph()
371        for b in branches:                     # replays must advance each run's private RNG
372            if getattr(b.closure, "generator", None) is not None:
373                g.register_generator_state(b.closure.generator)
374        with torch.cuda.graph(g):
375            one_round(torch.cuda.current_stream())
376        for _ in range(n_steps - n_warmup):
377            g.replay()
378    torch.cuda.synchronize()
379    return [b.finish() for b in branches]

true_score(): the exact score of a Gaussian mixturelines 382–400

The formula that makes this project possible. For a mixture with centres mk, common variance v and weights πk:

score(x) = Σ_k r_k(x) · (m_k − x) / v r_k(x) = softmax_k( log π_k − |x − m_k|² / 2v )

rk is the responsibility: how much x "belongs" to mode k. So the score is an arrow from x towards a weighted average of the centres. Points midway between two modes are pulled both ways, and that is where hallucinations are born.

After noising to level ᾱ the mixture is still a Gaussian mixture, with centres √ᾱ·μk and variance ᾱσ² + (1−ᾱ). So the exact score is known at every step. log_weights just prepares log π for the unequal-weights variant.

382# --------------------------------------------------------------------------------------
383# the exact sampler: the GMM score in closed form (no network), used to build the atlas
384#   s(x) = sum_k r_k (mu_k - x) / v,  r = softmax_k(log pi_k - |x - mu_k|^2 / 2v)
385# at noise level abar the noised mixture has means sqrt(abar) mu_k, variance abar sigma^2 + 1 - abar
386# --------------------------------------------------------------------------------------
387@torch.no_grad()
388def true_score(X, Mt, v, logw=None):
389    logits = -torch.cdist(X, Mt) ** 2 / (2 * v)
390    if logw is not None:
391        logits = logits + logw
392    return (torch.softmax(logits, 1) @ Mt - X) / v
393
394
395def log_weights(weights, device=None):
396    """log pi (1, K) for true_score / the flow velocity, or None when weights is None."""
397    if weights is None:
398        return None
399    w = weights.to(device) if device is not None else weights
400    return torch.log(w.clamp_min(1e-30))[None, :]

_exact_eps(): the score, written as a noise predictionlines 403–407

The learned network predicts noise ε, not the score. The two are related by ε = −√(1−ᾱ) · score, so this converts the exact score into exactly what a perfect network would output. Now the exact and learned samplers can share the same update rule.

403@torch.no_grad()
404def _exact_eps(x, means_t, ab, variance, logw=None):
405    """The exact score at noise level `ab`, as an eps-prediction."""
406    v = ab * variance + (1 - ab)
407    return -torch.sqrt(1 - ab) * true_score(x, torch.sqrt(ab) * means_t, v, logw)

_ddim_step(): one deterministic DDIM steplines 410–414

From noise level ᾱ to level ᾱ′, given a noise estimate ε:

x₀_guess = (x − √(1−ᾱ)·ε) / √ᾱ ← "what the clean point probably is" x′ = √ᾱ′ · x₀_guess + √(1−ᾱ′) · ε ← re-noise it to the next level

No fresh randomness enters, which is why every seed has one fixed fate. Going to a lower noise level moves towards data; going to a higher one moves back towards the seed.

410@torch.no_grad()
411def _ddim_step(x, eps, ab, abp):
412    """One deterministic DDIM update from noise level `ab` to `abp`."""
413    x0 = (x - torch.sqrt(1 - ab) * eps) / torch.sqrt(ab)
414    return torch.sqrt(abp) * x0 + torch.sqrt(1 - abp) * eps

_ddim_transport(): many steps with the exact scorelines 417–432

Moves points through a list of noise levels using _exact_eps and _ddim_step. With order="heun" (the default) each step is taken twice: once to guess the end point, then again with the noise estimate averaged between start and guessed end. That is second-order accurate, and precise enough that data → seed → data returns every point to the same label.

inplace=True overwrites the input tensor instead of copying it. At d = 512 an anchor set can be ~15 GB, so a copy may not fit.

417@torch.no_grad()
418def _ddim_transport(Xd, means_t, order, levels, variance, chunk=50000, logw=None, inplace=False):
419    """Carry points along the exact-score DDIM map over `levels` [(ab, abp), ...].
420    'euler' uses eps at the start; 'heun' averages it with eps at the predicted end point
421    (second order: data -> seed -> data round-trips to the same label). inplace=True reuses
422    Xd's memory (multi-GB anchor sets)."""
423    heun = str(order).lower() == "heun"
424    X = Xd if inplace else Xd.clone()
425    for ab, abp in levels:
426        for s in range(0, X.shape[0], chunk):
427            xs = X[s:s + chunk]
428            eps = _exact_eps(xs, means_t, ab, variance, logw)
429            if heun:
430                eps = 0.5 * (eps + _exact_eps(_ddim_step(xs, eps, ab, abp), means_t, abp, variance, logw))
431            X[s:s + chunk] = _ddim_step(xs, eps, ab, abp)
432    return X

backtrack_true(): data → seedlines 435–441

Walks the noise levels upwards (ᾱ0 → ᾱT−1): a point in data space becomes the seed that the exact sampler would have turned into it. Step 2 of the atlas.

The same walk downwards: the exact sampler proper. It is the inverse of backtrack_true. Used to label calibration seeds, in the start-page figure and in rank_probe.

ball_anchors(): step 1 of the atlaslines 451–475

For every mode k:

  • b points uniformly inside the R99 ball, labelled k. "Uniform in a ball" needs radius R99·u1/d with u uniform in [0, 1]: in d dimensions most of a ball's volume is near its edge, and the power 1/d puts the points there accordingly.
  • b × shell_frac points in the band from R99 to R99 + 2σ, labelled −1. These represent "just missed the mode": the hallucination class.

The labels come from label_fate itself, so they follow exactly the rule the ground truth uses. torch.addcmul(..., out=...) writes straight into one pre-allocated tensor to avoid temporary copies.

451# --------------------------------------------------------------------------------------
452# labelled anchors, placed around the modes in data space (callers carry them back to seeds)
453# --------------------------------------------------------------------------------------
454@torch.no_grad()
455def ball_anchors(means_t, R99, n_per_mode, shell_frac=0.5, shell_sigma=2.0, sigma=None,
456                 seed=0, device=None):
457    """Per mode: n_per_mode points uniform in the R99 ball plus shell_frac * n_per_mode points in
458    the band R99 .. R99 + shell_sigma * sigma, labelled by label_fate (so {k, -1}). One tensor
459    filled in place (at d=512 it can be ~15 GB)."""
460    K, d = means_t.shape
461    g = torch.Generator(device=device).manual_seed(seed)
462    n_shell = max(1, int(round(shell_frac * n_per_mode)))
463    per_mode = n_per_mode + n_shell
464    P = torch.empty(K * per_mode, d, device=device)
465    for k in range(K):
466        s0 = k * per_mode
467        u = torch.rand(n_per_mode, generator=g, device=device) ** (1.0 / d)     # uniform in the ball
468        dirs = torch.randn(n_per_mode, d, generator=g, device=device)
469        dirs /= dirs.norm(dim=1, keepdim=True)
470        torch.addcmul(means_t[k], (R99 * u)[:, None], dirs, out=P[s0:s0 + n_per_mode])
471        r = R99 + shell_sigma * sigma * torch.rand(n_shell, generator=g, device=device)
472        dirs = torch.randn(n_shell, d, generator=g, device=device)
473        dirs /= dirs.norm(dim=1, keepdim=True)
474        torch.addcmul(means_t[k], r[:, None], dirs, out=P[s0 + n_per_mode:s0 + per_mode])
475    return P, label_fate(P, means_t, R99)

altered_knn_anchors(): rings instead of a filled balllines 478–503

The anchors for the altered kNN predictor. Per mode, 5 concentric spheres at 0.3, 0.6, 0.9, 1.2 and 1.5 × R99. All of them are labelled with the mode, even the two rings outside R99; there is no hallucination class here. Instead each ring has a weight that falls with its radius (linearly from 0.84 to 0.2, or a Gaussian). altered_knn later calls a seed a hallucination when the vote of its neighbours is unsure, not because a neighbour was labelled −1.

478@torch.no_grad()
479def altered_knn_anchors(means_t, R99, n_per_mode, n_rings=5, r_max=1.5, weight="linear",
480                        w_min=0.2, sigma=None, seed=0, device=None):
481    """Per mode: n_rings spheres of radius R99 * r_max * j / n_rings, all labelled with the mode
482    (no hallucination class) and weighted by a radius-decaying confidence (linear | gaussian).
483    Returns P (n, d), y (n,), w (n,)."""
484    K, d = means_t.shape
485    g = torch.Generator(device=device).manual_seed(seed)
486    per_ring = max(1, n_per_mode // n_rings)
487    per_mode = n_rings * per_ring
488    radii = [R99 * r_max * j / n_rings for j in range(1, n_rings + 1)]
489    if weight == "gaussian":
490        w_ring = [float(np.exp(-r ** 2 / (2 * sigma ** 2))) for r in radii]
491    else:
492        w_ring = [1.0 - (1.0 - w_min) * (r / (R99 * r_max)) for r in radii]
493    P = torch.empty(K * per_mode, d, device=device)
494    y = torch.arange(K, device=device).repeat_interleave(per_mode)
495    w = torch.tensor(w_ring, device=device, dtype=torch.float32).repeat_interleave(per_ring).repeat(K)
496    for k in range(K):
497        for j, r in enumerate(radii):
498            dirs = torch.randn(per_ring, d, generator=g, device=device)
499            dirs /= dirs.norm(dim=1, keepdim=True)
500            s0 = k * per_mode + j * per_ring
501            blk = P[s0:s0 + per_ring]
502            torch.mul(dirs, r, out=blk); blk += means_t[k]      # == means_t[k] + r * dirs, bit for bit
503    return P, y, w
