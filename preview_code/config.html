Settings and setup: conf/

Every knob of the experiment, where it lives and what it does.

Nothing in the code has a hard-coded experiment setting: everything is read from conf/ through Hydra. conf/config.yaml picks one file from each folder ("group"); any value can be changed on the command line without editing a file:

python code/main.py process=flow # pick another file of a group python code/main.py sweep.d=[16,64] sweep.K=[4,8] # change values python code/main.py train.lr=5e-4 run_id=lr_test # a result-changing setting → a new run_id

Settings that change results are locked per run (see runstate): change them together with a new run_id.

README.md

The repository's own READMElines 1–114

Setup, how to run, the output layout and the method notes, as the author wrote them. The README's explanation of why 150 steps hallucinate ("small discretisation error") is plausible. For DDIM, part of the effect may also be the schedule issue described at make_schedule.

  1# Seed-fate atlas
  2
  3Which initial noise seeds make a diffusion (or flow-matching) model **hallucinate**?
  4
  5Data is a Gaussian mixture of K modes on a sphere in d dimensions. A seed x ~ N(0, I) has a
  6**fate**: the mode whose 99%-mass ball (radius R99) its sample lands in, or *hallucination* if it
  7lands in none. Because the mixture's exact score is known in closed form, we can plant labelled
  8points around the modes, carry them back to seed space with the exact field, and fit
  9predictors of a seed's fate from them (the *atlas*). Each predictor is scored against the
 10fates the **learned** sampler actually produces.
 11

 55## Runs are named and additive
 56
 57A run is a **name** (`run_id`, default `abc123`); everything lives in `output/<run_id>/`:
 58
 59```
 60run.json, history.log, invocations/        settings, one line / one config per invocation
 61checkpoints/<process>/<variant>/           checkpoints/model_d<d>_K<K>_s<seed>.pt, gt_cache/, manifest.json
 62<process>/<variant>/T<T_true>/             cells/d<d>_K<K>_s<seed>.json   (the result rows)
 63                                           results.json, results.csv, results_per_seed.csv
 64                                           table.tex, table.png, <model>.png, anchors_<b>/
 65logs/                                      scripts/main.sh job logs
 66```
 67
 68`<variant>` is `unweighted` or `weighted` (`data.weighted`: random mixing weights). Every stage
 69skips what already exists, so re-running a run resumes it and a sweep split into pieces (other
 70d, more seeds, another anchor budget, another T_true or predictor) gives the files of one big
 71invocation. The first invocation records the settings in `run.json`; a later one that changes
 72how cells are computed (training recipe, eval size, a predictor's hyper-parameters, ...) is
 73refused (`strict_run=false` overrides). Use a new `run_id` for a new experiment.
 74
 75**Several machines.** Run the same `run_id` elsewhere (e.g. `DIMS="512"`), copy that machine's
 76`output/<run_id>/` back, then
 77
 78```bash
 79python code/combine.py /path/to/copied/abc123 --dry-run    # report first
 80python code/combine.py /path/to/copied/abc123              # merge + rebuild results and figures
 81```
 82
 83It checks the settings match, copies what is missing, merges cell rows and manifests, and
 84never mixes a model with results computed from a different model of the same cell.

 86## Method notes
 87
 88- **Ground truth** = fates of `eval.n_eval_per_mode * K` seeds under the learned sampler,
 89  cached at train time. Metrics: full accuracy, mode accuracy / macro F1, hallucination
 90  precision / recall / F1. Every number is mean ± std over `n_seeds` repeats (seeds 0, 100,
 91  200, ...), each with its own mode placement, model and eval seeds.
 92- **Training recipe** (`conf/train/base.yaml`): Adam, cosine lr decay, gradient clipping, EMA
 93  weights; retried with more steps while the probe hallucination rate exceeds `hall_target`.
 94  Width 256 for d ≤ 64, 1024 above (the R99 margin shrinks like 1/√d). Each seed has its own
 95  RNG, so training seeds together (one CUDA graph, ~15x faster) or apart gives the same model.
 96- **T_train = 500.** At 150 steps even the *exact* score hallucinates in high d (15/52/93/100 %
 97  at d = 32/64/128/256): a mode's 99% ball is a shell of relative width ~1.2/√d, so small
 98  discretisation error ejects samples. With T = 500 the exact score stays ≤ 0.6 % up to d = 256.
 99- **Exact field.** DDIM: closed-form GMM score, Heun steps (data → seed → data round-trips to
100  the same label). Flow: the marginal OT velocity including the within-mode variance.
101- **Other solvers of the DDIM network** (`process=heun|rk45|dpmpp2m`, `code/processes/{heun,rk45,dpmpp2m}.py`, shared base `pf_ode.py`).
102  DDIM is the Euler method for the probability-flow ODE dy/dσ = ε_θ(x, t) (y = x/√ᾱ,
103  σ = √((1−ᾱ)/ᾱ)), so the same trained network can be integrated by any ODE solver. These three
104  load `checkpoints/ddim/` (they are never trained; phase 1 skips them), step over the same
105  T_train grid and share DDIM's exact field and anchors; only the ground truth (where the learned
106  sampler sends each seed) differs, cached under `checkpoints/<process>/`. Heun: Euler predictor +
107  trapezoid corrector (2 network calls / step); RK45: fixed-step Dormand–Prince, 5th order
108  (6 calls); DPM-Solver++(2M): 2nd-order multistep in log-SNR on the x0-prediction (1 call, its
109  first-order step is DDIM). Stochastic samplers (DDPM, DPM-Solver++ SDE) are not included: a seed
110  has no single fate under them.
111- **Ground-truth cache.** `gt_cache/` stores the evaluation seeds themselves with their fates
112  (and the GPU that made them); evaluation reads the points back instead of regenerating them.
113- **Anchors** (`conf/anchors/`): per mode, b points uniform in the R99 ball plus b/2 in the band
114  R99 .. R99 + 2σ (hallucination class); altered_knn uses weighted concentric rings instead.
