train.py and evaluate.py never ask "is this DDIM or flow?". They call five methods, and each process implements them:

Process: the shared partlines 23–60

  • The constructor stores the mode centres, the variance σ², the number of steps T and the mixing weights (plus their logarithms, which the exact field needs).
  • seeds(N, d, seed): N standard-normal points from their own generator, drawn on the CPU and then moved to the device. The GPU's generator can lay out its numbers differently on another GPU model, so the same seed would not give the same points on every machine; the CPU's does.
  • ckpt_process: None for a process with its own models. Heun, RK45 and DPM-Solver++(2M) (their shared base pf_ode.py) set it to "ddim": they load the DDIM checkpoints and are never trained.
  • arch, n_train, optim_kwargs: read the network size, training-set size and recipe from the configuration.
  • label(model, X0, R99): seeds → fates. Pass model=None to use the exact field instead of the network.

Flow matching in one paragraphlines 1–15

Instead of adding and removing noise, flow matching learns a velocity field: at time t, which way and how fast should a point move so that, starting from noise at t = 0, it arrives at data at t = 1? With the "optimal transport" path used here, each training pair (noise x₀, data x₁) is joined by a straight line:

position ψ_t = (1 − (1 − σ_min)·t)·x₀ + t·x₁ velocity u = x₁ − (1 − σ_min)·x₀

Sampling integrates the learned velocity from t = 0 to t = 1 with an ODE solver.

 1"""processes/flow.py — flow matching with the optimal-transport path (Lipman et al. 2022, Ex. II).
 2
 3t = 0 is noise, t = 1 is data. With s_t = 1 - (1 - sigma_min) t:
 4    path    psi_t(x0) = s_t x0 + t x1                       (Eq. 22)
 5    target  u_t       = x1 - (1 - sigma_min) x0             (Eq. 23)
 6The network is a velocity field, integrated t: 0 -> 1 to sample. The exact field is the
 7marginal OT velocity of the GMM in closed form, keeping the within-mode variance (without it
 8the field is 1/sigma_min-stiff at t = 1 and the backtrack is not invertible).
 9"""

FlowOTProcess and its training steplines 18–47

The time grid is T evenly spaced points from 0 to 1. So unlike DDIM, a different T only changes the step size, never the start or end.

One training step: take data x₁ and noise x₀, a random time t, the point ψt on the line between them, and train the network to output the line's velocity. The network's time input is t rounded to the nearest grid index, so the same ScoreNet as DDIM can be used.

18class FlowOTProcess(Process):
19    name = "flow"

21    def __init__(self, means_t, variance, T, device, cfg, weights=None):
22        super().__init__(means_t, variance, T, device, cfg, weights)
23        p = cfg.process
24        self.sigma_min = float(p.sigma_min)
25        self.solver = str(p.solver)                             # learned sampler
26        self.true_solver = str(p.get("true_solver") or self.solver)   # exact field
27        self.ts = torch.linspace(0.0, 1.0, T, device=device)

29    def train_closure(self, K, d, batch, seed):
30        torch.manual_seed(seed)
31        model = core.ScoreNet(d, **self.arch(d)).to(self.device)
32        oms = 1.0 - self.sigma_min
33        g = core.step_generator(seed, self.device)
34        draw = core._minibatch(self.means_t, self.variance, batch, self.n_train(), seed,
35                               self.device, self.weights, g)
36
37        def step():
38            x1 = draw()
39            x0 = torch.randn(batch, d, generator=g, device=self.device)
40            t = torch.rand(batch, generator=g, device=self.device)
41            psi = (1 - oms * t)[:, None] * x0 + t[:, None] * x1            # Eq. 22
42            target = x1 - oms * x0                                         # Eq. 23
43            ti = (t * (self.T - 1)).round().long().clamp(0, self.T - 1)    # time-embedding index
44            return ((model(psi, ti) - target) ** 2).mean()
45
46        step.generator = g
47        return model, step

_step(): one ODE steplines 49–64

Four standard solvers: Euler (one velocity per step), midpoint and Heun (two), RK4 (four). More evaluations per step means more accuracy for the same number of steps. The learned sampler uses Euler by default and the exact field uses Heun.

49    # ---- ODE integration on the uniform grid self.ts ----
50    def _step(self, f, x, t, dt, solver):
51        if solver == "euler":
52            return x + dt * f(x, t)
53        if solver == "heun":
54            k1 = f(x, t)
55            return x + 0.5 * dt * (k1 + f(x + dt * k1, t + dt))
56        if solver == "midpoint":
57            return x + dt * f(x + 0.5 * dt * f(x, t), t + 0.5 * dt)
58        if solver == "rk4":
59            k1 = f(x, t)
60            k2 = f(x + 0.5 * dt * k1, t + 0.5 * dt)
61            k3 = f(x + 0.5 * dt * k2, t + 0.5 * dt)
62            k4 = f(x + dt * k3, t + dt)
63            return x + (dt / 6.0) * (k1 + 2 * k2 + 2 * k3 + k4)
64        raise ValueError(f"unknown solver {solver!r}")

_integrate(): run the solver over the whole gridlines 66–75

Forwards (t: 0 → 1, seed → data) or backwards (t: 1 → 0, data → seed) with a negative step, in chunks of 50 000 points.

66    def _integrate(self, f, X, chunk, solver, backward=False, inplace=False):
67        """Integrate dx/dt = f(x, t) over the grid, t: 0 -> 1 (or 1 -> 0 when backward)."""
68        dt = 1.0 / (self.T - 1)
69        X = X if inplace else X.clone()
70        steps = reversed(range(1, self.T)) if backward else range(self.T - 1)
71        for i in steps:
72            t = float(self.ts[i])
73            for s in range(0, X.shape[0], chunk):
74                X[s:s + chunk] = self._step(f, X[s:s + chunk], t, -dt if backward else dt, solver)
75        return X

_true_velocity(): the exact velocity of a Gaussian mixturelines 86–103

The flow version of true_score. At time t, a point from mode k is distributed as N(t·μk, vart·I) with vart = t²σ² + st². Given a position x, standard Gaussian conditioning gives the expected data point, and the velocity follows from it:

E[x₁ | x, mode k] = μ_k + gain · (x − t·μ_k), gain = t·σ² / var_t velocity(x, t) = (Σ_k r_k · E[x₁ | x, k] − (1 − σ_min)·x) / s_t

with responsibilities rk as before. The docstring explains why the within-mode variance σ² is kept: without it the field becomes extremely steep near t = 1 and the backward integration cannot undo the forward one.

 86    @torch.no_grad()
 87    def _true_velocity(self, x, t):
 88        """Marginal OT velocity (E[x1 | x_t = x] - (1 - sigma_min) x) / s_t of the GMM.
 89
 90        x_t | k ~ N(t mu_k, var_t I) with var_t = t^2 sigma^2 + s_t^2, so
 91        E[x1 | x, k] = mu_k + gain (x - t mu_k) with gain = t sigma^2 / var_t, and the modes are
 92        weighted by their posterior responsibilities r_k (mixing weights included)."""
 93        oms = 1.0 - self.sigma_min
 94        st = max(1.0 - oms * t, 1e-6)
 95        M = self.means_t
 96        var_t = t * t * self.variance + st * st
 97        logits = -torch.cdist(x, t * M) ** 2 / (2 * var_t)
 98        if self.logw is not None:
 99            logits = logits + self.logw
100        r = torch.softmax(logits, dim=1)
101        gain = t * self.variance / var_t
102        m_bar = (1 - t * gain) * (r @ M) + gain * x               # = sum_k r_k E[x1 | x, k]
103        return (m_bar - oms * x) / st

Same DDIM network, other ODE solvers (the shared base)lines 1–28

DDIM's deterministic sampler is the Euler method for one ODE, the probability-flow ODE of the diffusion. Written in rescaled variables it is simply

dy/dσ = ε_θ(x, t), y = x / √ᾱ, σ = √((1 − ᾱ)/ᾱ), x = y / √(1 + σ²)

so the network that DDIM was trained with can be integrated by any ODE solver. Only the discretisation changes, never the model. The three processes (heun.py, rk45.py, dpmpp2m.py, one solver each) load checkpoints/ddim/ untouched (they are never trained; phase 1 skips them) and step over the same T_train grid:

processsolverordernetwork calls / step
heunEuler predictor + trapezoid corrector22
rk45fixed-step Dormand–Prince (scipy's RK45 without step control)56
dpmpp2mDPM-Solver++(2M), multistep in log-SNR21

The exact field, the anchors and the calibration seeds are DDIM's, so the atlas the predictors learn is the same; only the ground truth (where each solver sends the evaluation seeds) differs. It is cached under checkpoints/<process>/, and results go to output/<run_id>/<process>/. Stochastic samplers (DDPM, DPM-Solver++ SDE) are left out: under them a seed has no single fate to predict.

PFODEProcess: DDIM with another sample()lines 31–71

  • Inherits everything from DDIMProcess: the schedule ᾱ, the exact field, true_order. ckpt_process = "ddim" tells train.py and evaluate.py where its models are.
  • sig: σ at each grid index, increasing with the index (index T−1 is noise).
  • train_closure refuses: train process=ddim instead.
  • sample loops over chunks outside the steps, because DPM-Solver++ keeps the previous step's prediction per point.
  • _eps asks the network at a grid index; _index_of turns a σ that lies between two grid points into a fractional index (the time embedding is continuous, so the network can be asked in between). _f is the right-hand side dy/dσ.
31class PFODEProcess(DDIMProcess):

52    # ---- the ODE in (y, sigma) ----
53    def _eps(self, model, x, idx):
54        """The network's eps at grid index `idx` (fractional between grid points: the time

56        return model(x, torch.full((x.shape[0],), float(idx), device=x.device))

58    def _index_of(self, sigma):

Heunlines 8–21

Take a DDIM (Euler) step to predict the end point, ask the network there too, and redo the step with the average of the two noise predictions. Both evaluations sit on grid points, so the network is only asked about times it was trained on. It is the learned-network twin of the exact field's true_order=heun transport; the unit test checks they match step for step when fed the exact noise.

 8class HeunProcess(PFODEProcess):
 9    """Heun: an Euler (= DDIM) step to predict the end point, then the trapezoid of the slopes
10    at both ends. Both slopes sit on grid points, so the network is only asked about times it
11    was trained on. Written with core._ddim_step, it is the learned-network twin of the exact
12    field's `true_order=heun` transport."""
13    name = "heun"
14
15    def _solve(self, model, X):
16        for i in reversed(range(1, self.T)):
17            ab, abp = self.abar[i], self.abar[i - 1]
18            eps = self._eps(model, X, i)
19            eps = 0.5 * (eps + self._eps(model, core._ddim_step(X, eps, ab, abp), i - 1))
20            X = core._ddim_step(X, eps, ab, abp)
21        return X

Works in (y, σ): six slopes per step at σ between the two grid points, combined with the 5th-order weights. y starts at x/√ᾱT−1 and is turned back into x at the end.

20class RK45Process(PFODEProcess):
21    """Fixed-step Dormand-Prince (the RK45 of scipy / MATLAB without step-size control): six
22    slopes per step, at sigma between the two grid points, combined with 5th-order weights."""
23    name = "rk45"
24
25    def _solve(self, model, X):
26        y = X / torch.sqrt(self.abar[self.T - 1])
27        for i in reversed(range(1, self.T)):
28            s0, s1 = float(self.sig[i]), float(self.sig[i - 1])
29            h = s1 - s0                                          # < 0: sigma decreases to data
30            k = []
31            for c, a in zip(_DP_C, _DP_A):
32                yi = y + h * sum(aj * kj for aj, kj in zip(a, k)) if a else y
33                idx = i if c == 0 else (i - 1 if c == 1 else None)
34                k.append(self._f(model, yi, s0 + c * h, idx))
35            y = y + h * sum(b * kj for b, kj in zip(_DP_B, k) if b)
36        return y * torch.sqrt(self.abar[0])

DPM-Solver++(2M)lines 11–35

With α = √ᾱ, s = √(1−ᾱ), λ = log(α/s) and the network's data prediction x̂₀ = (x − s·ε)/α, one step from s to t is

x_t = (s_t/s_s)·x_s − α_t·(e^(−h) − 1)·D, h = λ_t − λ_s

With D = x̂₀ this is exactly a DDIM step (used for the first step). Afterwards D blends the current and previous predictions, D = (1 + 1/(2r))·x̂₀ − (1/(2r))·x̂₀prev with r = hprev/h, which makes it second order for the cost of one network call per step.

11class DPMpp2MProcess(PFODEProcess):
12    """DPM-Solver++(2M): with alpha = sqrt(abar), s = sqrt(1 - abar), lambda = log(alpha / s) and
13    the network's data prediction x0 = (x - s eps) / alpha, one step s -> t is
14        x_t = (s_t / s_s) x_s - alpha_t (exp(-h) - 1) D,     h = lambda_t - lambda_s
15    with D = x0_s on the first step (exactly a DDIM step) and afterwards the 2nd-order blend
16        D = (1 + 1/(2r)) x0_s - (1/(2r)) x0_prev,             r = h_prev / h."""
17    name = "dpmpp2m"
18
19    def _solve(self, model, X):
20        ab = self.abar.double()
21        alpha, s = torch.sqrt(ab), torch.sqrt(1 - ab)
22        lam = torch.log(alpha / s)
23        x0_prev, h_prev = None, None
24        for i in reversed(range(1, self.T)):
25            eps = self._eps(model, X, i)
26            x0 = (X - float(s[i]) * eps) / float(alpha[i])
27            h = float(lam[i - 1] - lam[i])
28            if x0_prev is None:
29                D = x0
30            else:
31                r = h_prev / h
32                D = (1 + 0.5 / r) * x0 - (0.5 / r) * x0_prev
33            X = float(s[i - 1] / s[i]) * X - float(alpha[i - 1]) * (math.exp(-h) - 1) * D
34            x0_prev, h_prev = x0, h
35        return X
